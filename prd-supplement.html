PRD 补充约束 v0.2

竞彩足球页面复刻系统 | 补充需求文档 | 2026-08-09

1. 背景与目的

在 v0.1 PRD 基础上，经过实际复刻验证发现以下问题需要进一步严格约束。本补充文档作为 v0.1 PRD 的增量，所有条款优先级高于 v0.1 中可能冲突的描述。

核心问题：v0.1 PRD 仅要求"每完成一个页面复刻后进行视觉对比"，未明确要求每个标签页状态都需要独立视觉对比，导致大量标签页内容未被覆盖。审查显示标签页覆盖率仅 1.6%。

3. iframe 内容提取要求（新增）

关键约束：对于通过 iframe 加载内容的页面，禁止仅使用 HTTP 抓取的原始 HTML，必须从浏览器渲染后的 iframe contentDocument 中提取完整 DOM。

原因：HTTP 抓取不执行 JavaScript，拿到的 iframe HTML 可能是空壳或模板，缺少动态渲染的数据内容。这会导致复刻页面内容为空。

3.1 必须从浏览器提取的 iframe 内容

  • 球员统计（playerTechIframe）：通过 iframe.contentDocument.documentElement.outerHTML 提取渲染后的完整 DOM
  • 文字直播（textLiveIframe）：同上方式提取，确保 JS 渲染的文字内容被捕获
  • 所有其他动态 iframe：凡是通过 JavaScript 动态加载内容的 iframe，必须从浏览器渲染后的 DOM 提取

3.2 验证规则

  • 提取的 iframe HTML 内容长度必须 > 500 字符，否则标记为异常并保留 HTTP 版本作为回退
  • 每个 iframe 内容页面必须单独进行视觉对比
  • iframe 内容中的外部资源（CSS/JS/图片）也必须被内联

4. 视觉对比覆盖要求（强化）

4.1 逐标签页对比（必须）

v0.1 仅要求"每完成一个页面复刻后进行视觉对比"。现强化为：

强制要求：每个标签页/子状态都必须独立进行视觉对比。仅对主页面对比不足以发现标签页内容缺失或渲染错误。

4.2 对比维度（必须）

维度检查内容阈值异常处理
像素差异源页面 vs 复刻页面截图≤2% 忽略, 2-10% 重试, >10% 修复自动重试 → 人工介入
DOM 节点数源 HTML vs 复刻 HTML 节点数差异≤20% OK, 20-50% 警告, >50% 错误标记为 needs_retry
外部资源复刻页面中残留的外部 URL0 OK, 1-3 警告, >3 错误需补抓内联
控制台错误复刻页面加载时的 JS 错误/异常0 OK, 1-3 警告, >3 错误需检查 JS 注入

4.3 源截图捕获时机（必须）

源页面截图必须在浏览器渲染时同步捕获，不得在复刻完成后重新访问源站截图。原因：源站数据可能实时变化，异步截图会导致误判。

5. 自动化审查机制（新增）

5.1 审查模块要求

系统必须包含自动化审查模块（compare/audit.py），在每次复刻任务完成后自动执行，检查：

  • 页面覆盖率：所有预期页面是否都已生成
  • 对比覆盖率：所有已生成页面是否都有视觉对比记录
  • 标签页覆盖率：每个主页面的预期标签页是否都已生成
  • 空标签页检测：标签页内容是否为空（可能 iframe 未渲染）
  • 各维度异常统计：DOM/外部资源/控制台错误数量

5.2 审查报告

审查结果必须输出为 audit_report.json，包含：

  • 总页面数、有视觉对比页面数、对比覆盖率百分比
  • 预期标签页数、已生成标签页数、缺失标签页数、空标签页数
  • 按页面类型分布统计
  • 按状态分布统计（ok/warning/error/missing）
  • 有问题的页面明细列表

5.3 阻断条件

质量门禁：当审查发现以下情况时，任务应标记为"部分完成"并提示用户：
  • 对比覆盖率低于 95%
  • 标签页覆盖率低于 80%
  • 存在空标签页（iframe 内容未渲染）
  • 存在 DOM 差异 > 50% 的页面
  • 存在外部资源残留 > 3 个的页面

6. 页面类型 JS 交互保留要求（新增）

_freeze_rendered_page 删除所有 <script> 后，必须通过 js_injector 重新注入以下页面类型所需的交互函数：

页面类型必须注入的函数用途
列表页DateChange, isShowSclass, showHided 等日期切换、行显示/隐藏
分析页ShowIntegral, setType, changeVs2, r_close, t_onclick, hidOddsCmp积分榜切换、赔率类型切换、交锋数据切换
现场分析ShowIframe, ShowEventDetail, changeTechCount, changeJsq, changeLive, ShowTabContent标签切换、子标签切换、直播类型切换
联赛页changeRound, SelectScore, showHtml轮次切换、标签页切换
球队页ClickTechType技统类型切换
欧赔页OddsHistory, showFileter, CheckAll, clearFilter赔率历史、筛选器
亚盘页companyFilter, CheckAll, delCheck公司筛选、全选
角球/大小球companyFilter, CheckAll公司筛选
验证要求：注入的 JS 函数必须通过控制台错误检查验证其可正常执行。若控制台出现 [pageerror] 级别错误，需检查函数实现是否与页面 DOM 结构匹配。

7. 完整复刻流程检查清单

每个页面必须经过以下完整流程：
  1. HTTP 抓取原始 HTML
  2. Headless 浏览器渲染（执行原始 JS，等待动态数据加载）
  3. 同步捕获源页面截图（必须）
  4. 逐标签页切换并捕获 DOM + 截图（必须）
  5. 从浏览器 iframe contentDocument 提取已渲染内容（必须）
  6. 资源内联（CSS/JS/图片 → data URL 或内联标签）
  7. 冻结 DOM（删除原始 script）
  8. 注入页面类型专用 JS 交互函数
  9. 繁体转简体
  10. 注入水印
  11. 链接重写（指向本地复刻文件）
  12. 保存最终 HTML
  13. 视觉对比（4 维度：像素/DOM/外部资源/控制台）（必须）
  14. 运行自动化审查（必须）
